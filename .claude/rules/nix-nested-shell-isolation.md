# Rule: Nix Nested Shell Isolation (All R Projects)

See the companion doc for "What R_LIBS_SITE Is (and Is Not)".

## The Problem

When `nix-shell default.nix --run "Rscript ..."` is called from inside an
existing nix-shell (e.g. a global dev shell), the inner shell **inherits
`R_LIBS_SITE`** from the outer shell. That inherited value points to
`/nix/store/` paths compiled against the **outer** R binary.

The inner shell uses a *different* R binary (different nix store hash, even
if same R version string). When R loads a compiled package (Rcpp, lme4, brms),
the `.so` file was built for the outer R's ABI. The inner R's C runtime has
different symbol addresses and struct layouts. Result: **segfault on first
native call** (`dyn.load` → SIGSEGV).

The shellHook fix **corrects contamination** — it discards the inherited outer
paths and rebuilds R_LIBS_SITE from the inner shell's own closure. It does not
install anything.

## The Symptom

A `*** caught segfault ***` at `dyn.load()` inside `loadNamespace()`. Crashes
in Rcpp, lme4, brms, Matrix, or any package with compiled C/C++/Fortran. The
full traceback is in the companion doc.

## The Fix

Every rix-generated `default.nix` MUST have a `shellHook` that rebuilds
`R_LIBS_SITE` from the derivation's own dependency closure:

```nix
shell = pkgs.mkShell {
  buildInputs = [ rpkgs system_packages ];

  shellHook = ''
    R_LIBS_SITE=""
    for pkg in $buildInputs; do
      for dep in $(nix-store -qR "$pkg" 2>/dev/null); do
        if [ -d "$dep/library" ]; then
          case ":$R_LIBS_SITE:" in
            *":$dep/library:"*) ;;
            *) R_LIBS_SITE="''${R_LIBS_SITE:+$R_LIBS_SITE:}$dep/library" ;;
          esac
        fi
      done
    done
    export R_LIBS_SITE
    unset R_LIBS_USER
    unset R_LIBS
  '';
};
```

This scans the full closure (`nix-store -qR`) of `buildInputs`, finds all
directories containing R package libraries, and builds `R_LIBS_SITE` from
scratch. The inherited outer paths are discarded.

## When This Applies

- **Every** R project with a `default.nix` generated by `rix::rix()`
- **Every T-lang project** with R dependencies in `tproject.toml` -- see
  "T-lang Projects" section below
- Especially when Claude Code subagents run `nix-shell --run` from a session
  that is already inside a nix-shell
- Also applies when `default.sh` or `default.post.sh` is called from inside
  another nix-shell

## T-lang Projects: `t update` Strips the shellHook (CRITICAL)

T-lang generates `flake.nix` wholesale from `tproject.toml` via
`src/package_manager/nix_generator.ml` in
[b-rodrigues/tlang](https://github.com/b-rodrigues/tlang). The generated
shellHook does **NOT** contain the closure-rebuild block -- it is not yet in
the T-lang template (as of 2026-05-28, upstream fix tracked in llm#303). Every
`t update` run **discards** any hand-applied closure-rebuild block.

### Mandatory Workaround Until T-lang Template Is Fixed

Every T-lang R project MUST ship a `default.post.sh` in the project root that
re-applies the patch after `t update`. The script must:

1. Check for the `"Closure-rebuild"` marker (idempotency guard)
2. If absent, insert the closure-rebuild block immediately after
   `shellHook = ''` in `flake.nix`
3. Be committed to the project root alongside `flake.nix`

Reference implementation: `JohnGavin/historical` repo root `default.post.sh`.
Run `bash default.post.sh` **immediately** after every `t update`. Never commit
after `t update` without running `default.post.sh` first. The worked
required-workflow commands and the CI marker-check script are in the
companion doc.

Once the T-lang template bakes in the closure-rebuild block (llm#303),
`default.post.sh` is no longer needed for this purpose. Update this rule and
`t-lang-r-package.md` when that happens.

## Fix Options (Choose One)

| Option | How | Tradeoff |
|--------|-----|----------|
| **`--pure`** (Nix-idiomatic) | `nix-shell default.nix --pure --run "..."` | Strips ALL inherited env: clean R_LIBS_SITE but also loses `$HOME`, locale, SSH keys |
| **Closure-rebuild shellHook** (this rule) | Add shellHook to `default.nix` | Keeps env; corrects R_LIBS_SITE; ~5s overhead on shell entry |
| **`env -u R_LIBS_SITE`** at call site | `env -u R_LIBS_SITE nix-shell --run "..."` | Fragile — must be remembered on every call site |

`--pure` is the correct Nix-idiomatic solution when the caller controls the
call site. The shellHook is the right fix for agent invocations (where `--pure`
can't be guaranteed) and for interactive use via `default.sh`.

## What NOT To Do

- Ignoring segfaults and assuming "lme4/brms doesn't work in Nix" — it does,
  the inherited env var is the issue
- Reaching for `R_LIBS_SITE` manipulation thinking packages need to be "found"
  at runtime — all packages are pre-built; the issue is exclusively about
  which pre-built paths R is pointed at

## Verification

After adding the shellHook, `library(lme4)` must load from inside any
nix-shell with no `env -u` prefix needed. A worked verification command is in
the companion doc.

## Performance

The `nix-store -qR` closure scan adds ~5 seconds to shell entry. This is a
one-time cost per `nix-shell` invocation and is acceptable.
