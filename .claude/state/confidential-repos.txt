# Confidential-by-policy repos — llm's OWN list, consumed by
# repo_visibility.sh (JohnGavin/llm#794 item 1).
#
# Format: one entry per line — either a bare directory basename
# (e.g. "my-private-project") or an "owner/repo" GitHub identifier
# (e.g. "JohnGavin/my-private-project"). Lines starting with '#' are
# comments; a trailing '#...' on a data line is also treated as a comment.
# Blank lines are ignored.
#
# Purpose: some repos are technically PUBLIC on GitHub (or have no GitHub
# remote at all and would otherwise fall through to a weaker bucket) but
# must still never have their name/paths/domain detail appear in a public
# cross-project artifact this repo (llm) publishes — issues, PR bodies,
# comments. Any entry here is classified `confidential_by_policy` by
# repo_visibility.sh regardless of what `gh repo view` would otherwise say.
#
# This list is deliberately SEPARATE from
# `llmtelemetry::excluded_dashboard_projects()` (a different repo's R-level
# dashboard-scoping list) and from `.claude/state/trusted-contributors.txt`
# (a different concern — code-provenance trust, not publish-detail
# sensitivity). llm's own confidential-by-policy list exists because the
# pre-publish guard in THIS repo (private_repo_detail_guard.sh) must decide
# what to scan for using bash + `gh`, with no dependency on another
# project's R package being installed or loadable.
#
# To add an entry:
#   1. Confirm the repo is genuinely confidential-by-policy (not simply
#      "currently private" — that case is already covered by
#      `gh repo view --json visibility` and needs no entry here).
#   2. Add the basename or owner/repo string below.
#   3. Commit with a message referencing the decision/issue that added it.
#
# NOTE ON SHORT AND COMMON NAMES (llm#1183): entries here are matched at ANY
# length, unlike filesystem-discovered names which must clear
# PRIVATE_DETAIL_MIN_NAME_LEN (default 6). That is deliberate — a name is here
# because a human decided it must never be published, so the false-positive
# cost is theirs to weigh. But do weigh it: declaring a short or dictionary
# word (`crew`, `aver`, `data`) will block legitimate issues that merely use
# the word. Prefer the owner/repo form, or accept the noise knowingly.
#
# A declared entry does NOT need to exist on this machine, be checked out, or
# live under $REPO_VISIBILITY_SCAN_ROOT. Declaration alone is sufficient — that
# is the whole point of this list (llm#1183).
#
# WHERE REAL CONFIDENTIAL NAMES GO (roborev #10301): this file is TRACKED and
# PUBLIC — anyone with read access to this repo can read every line below.
# Committing a real confidential repo name here, even inside a guard whose
# whole purpose is protecting such names, publishes exactly what the guard
# exists to protect: a leak inside the leak-prevention mechanism itself.
#
# Real, currently-confidential names belong ONLY in the local, never-
# committed overlay at $REPO_VISIBILITY_CONFIDENTIAL_LOCAL_LIST (default
# ~/.config/confidential-repos.local.txt, mode 600, outside every repo).
# repo_visibility.sh reads BOTH this file and that overlay when building
# declared candidates and when classifying a repo — see
# `_confidential_entries()` in repo_visibility.sh. THIS file is for names
# that are already public knowledge, or synthetic (the canary below) — never
# for a name that is itself the confidential fact.
#
# Rule reference: .claude/rules/private-repo-detail-locality.md
# Issue: JohnGavin/llm#794

# Positive control. Not a real repo and never will be. This is the fixture a
# scheduled canary check (llm#1183 phase 5, not yet built) is intended to
# pipe through private_repo_detail_guard.sh as a synthetic publish payload,

#   echo 'body mentioning zzz-canary-never-a-real-repo' | private_repo_detail_guard.sh ...
